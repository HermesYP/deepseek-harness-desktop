## 4. Does "primary target: Windows, portable to macOS and Linux" hold?

| Claim | Verdict | Evidence |
|---|---|---|
| "Primary target: Windows" | **Partially supported, not stated as primary.** Windows x64 is a fully tooled release target (NSIS installer, EV signing, tray/caption UX, pwsh tool family, Windows ACL sandbox, PowerShell persistent tool as "the Windows counterpart"), and `check:ci:windows-*` gate families exist — but upstream publishes no priority ordering; macOS arm64/x64 receive equal release tooling and the repository's own test fixtures "replay on macOS/Linux" (`_upstream/AGENTS.md`). | `_upstream/package.json` (`package:desktop:win:x64`, `check:ci:windows-blocking/complete/observational-ready`), `_upstream/docs/tool-catalog.md` (`dsh-tool-pwsh-persistent`: "the Windows counterpart of the persistent bash tool"), `_upstream/AGENTS.md` ("Fixtures replay on macOS/Linux") |
| "Portable to macOS" | **Holds.** macOS x64 + arm64 are first-class shipped desktop targets with their own installer lanes (DMG+ZIP), notarization, and update feeds; macOS-specific UX (Dock, ⌘-shortcuts, vibrancy, ICNS, menu bar absence) is implemented. | `_upstream/apps/desktop/scripts/package-target.ts:61-75`, `_upstream/apps/desktop/README.md` |
| "Portable to Linux" | **Does NOT hold for the desktop product as shipped.** Upstream states: "Linux is not a supported Desktop release target." Linux is supported only beneath the harness layer (CLI/Web/headless): Linux x64/arm64 native platform packages (Landlock + flock), bwrap/Landlock sandbox rungs, `check:ci:linux-primary`, and a vestigial `linux: { target: ['AppImage'] }` builder stanza that no packaging command reaches. | `_upstream/apps/desktop/README.md`, `_upstream/native/system/docs/support-matrix.md`, `_upstream/package.json` (`check:ci:linux-primary`), `_upstream/apps/desktop/scripts/electron-builder-config.mjs:231-234` |

Bottom line: upstream's own matrix is **Windows x64 and macOS x64/arm64 (desktop) + Linux (CLI/Web/headless only)**. A port planning assumption of "primary Windows, portable to macOS" is consistent with the shipped matrix; "portable to Linux" is true only for the non-desktop harness and must not be read as a shipped Linux desktop target.
