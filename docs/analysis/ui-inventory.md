## 1. Routes and screens

There is NO URL router: no `location.hash`, `pushState`, `popstate`, or `hashchange` usage exists in `_upstream/packages/client` (grep across `packages/client/**/*.ts`), and `_upstream/apps/web/index.html` serves one SPA document with a single `#root` (`_upstream/apps/web/index.html`).
"Routing" in this product is four separate mechanisms: HTTP request-target routing, Conversation View selection, root panel selection, and right-sidebar tab routing.

| Mechanism | Rule | Evidence |
|---|---|---|
| HTTP route resolution (the `verify-client-route-resolution` gate) | App-owned routes (`api/…`, `plugins/…`, `open-in-app/…`) used as request targets in browser code must be document-relative (`api/x`); root-absolute/absolute request targets, relative app routes resolved against a `location` read, and unstripped `*_PATH`/`*_ENDPOINT` host route keys are rejected; a static reference producer (`packages/client/modules/src/index.ts`) must emit `url`/`src`/`href` fields document-relative | `_upstream/scripts/verify-client-route-resolution.ts` (rules `request-target`, `location-base`, `host-route-key`, `reference-producer`; `APP_ROUTE_PREFIX` at line 38), wired as `verify-client-route-resolution` in `_upstream/package.json` and `_upstream/scripts/run-gates.ts` |
| Conversation View selection | Views register into the `conversation.view` slot (`chat` order 0, `trajectory` order 10); a persisted per-session preference wins, else registered `chat`, else no View renders (never "first registered"); the tab bar hides with fewer than two Views; Coding Tools off hides Trajectory only | `_upstream/packages/client/ui-conversation/README.md` (Shell and standard props), `_upstream/packages/client/ui-conversation/src/client/view-selection.ts`, `_upstream/packages/client/ui-chat/src/client/apply.ts:179`, `_upstream/packages/client/ui-trajectory/src/client/index.ts:80` |
| Root panel selection | The root-scoped keyed `main` slot holds panels; `conversation` is the reserved key; `ctx.layout.selectPanel(id)` selects a global panel and `null` returns to the Conversation without changing the Session; shipped composition registers no extra global panel except the ones feature plugins add (Automation tasks, Plugins manager) | `_upstream/packages/client/ui-layout/README.md` (Global panel entries), `_upstream/packages/client/ui-layout/src/client/index.ts:172`, `_upstream/packages/client/ui-sidebar/README.md` (Global panel entries) |
| Right-sidebar tab routing | `ctx.sidebarRight.openResource(address, options?)` routes `dsh-resource://<type>/…` addresses through the tab-type registry (globs `patterns`, `canOpen`, priority bands `extension` > `builtin` > `fallback`, then longer pattern, then registration order); `ctx.sidebarRight.openTab(kind, options?)` opens page tabs | `_upstream/packages/client/ui-sidebar-right/README.md` (`ctxsidebarRight` and extension seats sections) |

Browser document title is a derived projection of the selected Session title with the build-configured product title (or localized `common.brand.localBuild`) as fallback: `_upstream/packages/client/ui-layout/src/client/DocumentTitle.tsx`, `_upstream/packages/client/ui-layout/README.md`.
Boot sequence: `apps/web/src/main.ts` runs `new AppWebEntry(container).run()`; the framework-free boot page renders immediately and shows one spinner whose CSS arc grows as plugin entries activate, plus per-entry status and named failures: `_upstream/packages/client/web/README.md` (What boot looks like, The boot page), `_upstream/packages/client/web/src/boot-page.ts`, `_upstream/packages/client/web/src/boot-page.module.css`, `_upstream/packages/client/web/src/loader-status.ts`, `_upstream/packages/client/web/src/mount.ts`.
The web shell composition is assembled by slot registration (the shell alone renders slot `'root'`): `_upstream/packages/client/ui-layout/src/client/index.ts:172` (root registration with children `sidebar`, `main`, `rightbar`, `shell.overlay`, `shell.leading`), `_upstream/packages/client/AGENTS.md` (Slot and props discipline).

Selection and persistence: provisional locale from `navigator.languages` (full tag then primary subtag, English fallback), replaced by the Host-backed `locale.preference` settings value on loopback pages (persisted in `$DSH_HOME/cordis.patch.yml`); non-loopback pages stay process-local; native shells may supply `__DSH_LOCALE__` with `read()`/`onChange()` (ordered OS languages before Client mount): `_upstream/packages/client/locale/README.md` (Choosing a language), `_upstream/packages/client/locale/src/locale-settings.ts`, `_upstream/apps/desktop/README.md` (shell locale paragraph).
